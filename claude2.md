## What this project is

A local-first, self-hosted **Flight Information Display System (FIDS)** that runs on Windows, macOS, and Raspberry Pi. Fetches real and simulated flight data, displays it as a proper airport-style departure/arrival board — in a browser kiosk window, on an LED matrix panel, or on a dedicated HDMI screen.

Built with: Python 3.11+, FastAPI, uvicorn, SQLite, WebSocket, Jinja2, PIL, psutil, packaging.  
pystray on macOS only — Windows uses a ctypes taskbar window (no extra deps).  
Mobile companion: React Native / Expo (iOS-first, in `mobile/`).

## Architecture

### Startup flow (desktop)
```
main()
  _load_dotenv()
  _install_crash_hooks()   ← sys.excepthook + threading.excepthook → bug_reporter.submit_crash()
  _run_desktop()
    _start_scheduler()     ← daemon thread
    _start_uvicorn()       ← daemon thread
    _wait_for_server()
    launch_app_window(/splash?next=/display)
    build_tray(on_quit, on_open_display)
    icon.run()             ← blocks main thread until os._exit(0)
```

### Platform tray / taskbar
- **Windows**: hidden `WS_EX_APPWINDOW` win32 window (ctypes, no extra deps). Shows in taskbar with app icon. Left-click (SC_RESTORE) → `on_open_display()`. Right-click → context menu: "Open Display" / "Quit Local Flight". Message loop in daemon thread; `run()` blocks on `Event.wait()`.
- **macOS**: pystray tray icon. Menu: Open Display + page links + Quit. Status color tracks scheduler health (green/amber/red).
- **Pi/Linux**: no-op stub, `run()` blocks on `time.sleep` loop.

### Data enrichment chain
```
AviationStack (schedule) [90 calls/month budget]
  → ADS-B Exchange / RapidAPI (position, aircraft type)   [primary]
  → OpenSky Network (position fallback)
  → schedule-only fallback
  → dedupe codeshares
  → JSON snapshot → ~/.localflight/storage/data/<IATA>/snapshots/
  → SQLite history (90-day retention)
  → WebSocket broadcast
  on error →
    operator Linear: linear_client.file_error()  (opt-in, env vars)
    developer Linear: bug_reporter.submit_crash() (always-on, deduped 6h)
```

### Crash reporting (three layers)
1. **Scheduler cycle errors** (`runtime.py`): every failed `run_loop()` iteration calls both `linear_client.file_error()` (operator, optional) and `bug_reporter.submit_crash()` (developer, always). Crash report includes traceback + last 50 log lines. Deduped per 6h via `~/.localflight/bug_report_dedup.json`.
2. **Unhandled main-thread exceptions** (`__main__._install_crash_hooks`): `sys.excepthook` catches anything that escapes to the top — calls `submit_crash()` with full traceback. KeyboardInterrupt / SystemExit excluded.
3. **Unhandled thread exceptions** (`__main__._install_crash_hooks`): `threading.excepthook` catches unhandled exceptions in any daemon thread (scheduler top-level, uvicorn, etc.).

### Linear integrations (do not confuse)
| | `linear_client.py` | `bug_reporter.py` |
|---|---|---|
| Target | Operator's own Linear workspace | Developer's "Local Flight Reports" workspace |
| Credentials | `LINEAR_API_KEY` + `LINEAR_TEAM_ID` env vars | Hardcoded (base64, isolated inbox) |
| Trigger | Scheduler cycle error | `/feedback` form submission OR auto crash |
| Function | `file_error()` | `submit_report()` / `submit_crash()` |
| Dedup | 6h via `linear_dedup.json` | 6h via `bug_report_dedup.json` |
| Optional? | Yes — silent if vars not set | No — always-on |

### WebSocket live push
- `ConnectionManager` in `server.py` — async queue, drains on broadcast
- `ui/events.py` publishes `snapshot_updated`, `config_updated`, and `scheduler_restarted`
- Scheduler → `_broadcast_update()` after snapshots; settings/API/profile/setup saves → `notify_config_updated()`
- Scheduler-relevant config changes (`airport_iata`, `airport_icao`, `refresh_seconds`, `source`) queue `restart_scheduler_and_notify()` so interval changes take effect immediately
- `display.html` holds one WS, reloads on `config_updated`, and forwards other messages via `postMessage` to iframes
- FIDS/Radar/Admin/mobile refresh on push events and keep lightweight fallback polling
- Clients reconnect with exponential backoff
- Mobile (`App.tsx`) subscribes and refreshes on `snapshot_updated`, `config_updated`, and `scheduler_restarted`

### Setup gate
- `SetupGateMiddleware` redirects everything to `/setup` until `~/.localflight/setup_complete` exists
- Exempt: `/setup`, `/api/setup/*`, `/api/airports/search`, `/static`, `/health`, `/ws`
- Scheduler deferred on first launch; setup watcher thread auto-starts it when marker appears
- `/api/setup/reset` deletes marker → re-run wizard

### Splash screen
- `/splash?next=<path>` — short animated boot screen (SVG mark + version badge)
- All desktop launchers and Pi kiosk service open `/splash?next=/display`
- First-run: `/splash?next=/setup`
- `tray.py._splash_url(path)` helper for opening display from tray/taskbar

### API call budget
- AviationStack: 90 calls/month (configurable), tracked in `~/.localflight/api_usage.json`
- `_check_and_increment_budget()` in `aviationstack_client.py` before each request
- All env vars read lazily — never at module import time

### Icons / build
- Source SVGs: `assets/icon_square.svg` (Windows), `assets/icon_circle.svg` (macOS)
- `build.py make_icons()`: tries `cairosvg` → pre-rendered PNG fallback → PIL placeholder
- PyInstaller embeds icon in exe; taskbar window extracts it via `ExtractIconExW(sys.executable)`

### Version
- Single source: `version` in `pyproject.toml` (currently `0.2.3b1`)
- Runtime: `importlib.metadata.version("localflight")` with `"0.2.3b1"` fallback
- Injected as `app_version` Jinja2 global in `server.py`
- `LocalFlight.spec` reads it for macOS `CFBundleShortVersionString`

### Mobile companion (`mobile/`)
- iOS-first React Native / Expo app, LAN client to the Python server
- Server URL stored in Expo SecureStore; expects LAN address, not localhost
- Reads: `/api/health`, `/api/config`, `/api/admin/system`, `/api/admin/budget`, `/api/admin/connections`, `/api/admin/updates`, `/api/fids`, `/api/radar`, `/api/history`, `/api/metar`, `/api/fids/detail`
- WS: subscribes to `/ws`, refreshes on `snapshot_updated`, `config_updated`, and `scheduler_restarted`; server update interval is used as a capped fallback poll
- Main bottom nav contains only FIDS, RADAR, HISTORY, SETTINGS; Matrix/Admin are launched from Settings
- UI follows iOS airport-board mockup: Flight Island, departure-airport/live header, UTC/local clock, METAR strip, FIDS tabs, pinned flight, compact rows, bottom nav
- Mobile Settings can edit airport/source/update interval, save local profiles, restart scheduler, open Matrix/Admin, submit feedback, and open Buy Me a Coffee
- Mobile crash reporting lives in `mobile/src/crash/` and sends `/api/feedback/crash` with mobile reporter context
- Admin mutating controls remain limited until QR pairing / per-device tokens exist; scheduler restart/config changes are current trusted-LAN exceptions
- Node/npm on Mac/Xcode machine — `npm install`, `npx expo install --fix`, `npm run doctor`, `npm run ios`

## Key API endpoints

| Endpoint | Description |
|---|---|
| `GET /api/config` | Current AppConfig as JSON |
| `PATCH /api/config` | Update config fields; broadcasts `config_updated`; restarts scheduler for airport/source/interval changes |
| `GET /api/fids` | JSON FIDS rows |
| `GET /api/fids/detail?callsign=` | Live position + 7-day history for one flight |
| `GET /api/radar` | Aircraft positions (blips) |
| `GET /api/metar` | Decoded + raw METAR |
| `GET /api/history` | Recent flights from SQLite |
| `GET /api/history/flight?callsign=` | Callsign history |
| `GET /api/history/stats` | DB size, row count |
| `GET /api/admin/system` | Uptime, memory, CPU, version (needs psutil) |
| `GET /api/admin/budget` | AviationStack call count vs limit |
| `GET /api/admin/connections` | WS client count + device pings |
| `GET /api/admin/updates` | GitHub release check (1h cache) |
| `GET /api/admin/scheduler` | Scheduler thread status |
| `POST /api/admin/scheduler/restart` | Stop sleeping scheduler loop, reload config/env, start fresh cycle, broadcast `scheduler_restarted` |
| `GET /api/health` | `{"status":"ok"}` — mobile heartbeat |
| `POST /api/feedback` | `{title, description, client_context}` → developer's Linear |
| `POST /api/feedback/crash` | Auto-file mobile/server crash report with deduplication |
| `POST /api/admin/ping` | Device ping (matrix client keepalive) |
| `POST /api/setup/complete` | Save config, write .env, mark setup done |
| `POST /api/setup/reset` | Delete setup_complete → re-run wizard |
| `GET /api/setup/test-aviationstack?key=` | Validate key without saving |
| `GET /api/setup/test-rapidapi?key=` | Validate RapidAPI key without saving |
| `POST /api/quit` | Graceful shutdown |
| `WS /ws` | WebSocket push — emits `snapshot_updated`, `config_updated`, `scheduler_restarted` |

## Code style / conventions

- Python 3.11+, `from __future__ import annotations`, type hints throughout
- FastAPI web layer, Jinja2 templates
- **No module-level env var reads** — always lazy inside functions (avoids race with `_load_dotenv()`)
- **Non-fatal pattern** — risky ops wrapped in `try/except`, log warning, continue
- `os._exit(0)` for hard shutdown (bypasses uvicorn signal handling)
- Jinja2: `{% from "_nav.html" import topnav %}`, active state via `active="pagename"` param
- `app_version` Jinja2 global injected in `server.py` — available in all templates
- History writes, enrichment fallbacks, WS broadcasts, Linear calls are all non-fatal
- Crash reporter calls are non-fatal (double-wrapped in try/except)
