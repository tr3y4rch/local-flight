Beacon Tools Network

Public relay for Local Flight, with admin kept separate.

The hosted relay helps Local Flight clients use shared cached data without shipping provider keys inside every install.

Public relay: relay.beacontools.cc Admin: operator-only

Public client host

https://relay.beacontools.cc
Local Flight Relay and Mobile Standalone use public `/v1/*` API paths for activation, schedules, radar, METAR, reports, status, heartbeat, and mobile summaries.

Operator host

https://network.beacontools.cc/admin
This is the operator admin surface. It is not part of normal public client navigation and should require operator authentication.

What the relay does

Shared data, guarded usage.

  • Caches shared airport schedule snapshots so many installs can watch the same airport without each one calling a paid provider.
  • Applies activation, rate limits, refresh policies, and stale-safe serving to protect shared upstream quotas.
  • Supports Mobile Standalone and Local Flight Relay without requiring user accounts.
  • Accepts consent-based reports and diagnostics through the relay reporting path.
If Standalone is offline

Basic checks first.

  1. Check the phone has internet access. Standalone does not use your desktop or Pi server.
  2. Try again after a few minutes. Relay-backed data can intentionally serve stale cached boards during upstream problems.
  3. Check whether only radar is affected. Radar refresh and range are intentionally limited on mobile.
  4. If it still fails, use Support and include the app mode, airport, approximate time, and diagnostics setting.

Public safety note

Relay responses and cached board data are informational display aids. They can be delayed, incomplete, wrong, unavailable, or intentionally stale. Do not use them for professional or safety-critical aviation decisions.
