Beacon Tools Network

The shared relay that helps Local Flight stay simple.

The Beacon Tools relay gives Local Flight and Mobile Standalone a safe shared data path without putting provider keys inside every install.

Public relay: relay.beacontools.cc Shared cached schedules Safety-first refresh limits

What your app talks to

https://relay.beacontools.cc
Local Flight Relay and Mobile Standalone use this public relay for activation, shared schedules, radar/weather helpers, mobile summaries, and consent-based reports.

What stays separate

The public relay only exposes the client paths normal installs need. Maintenance, monitoring, provider keys, and operational controls stay outside public navigation and are not part of the end-user app flow.

What the relay does

Shared data, gentle limits.

  • Reuses cached airport schedules so many hobby installs can watch the same airport without each one burning a separate provider call.
  • Keeps refreshes intentionally modest, which protects shared provider quotas and makes the free/community path more sustainable.
  • Lets Mobile Standalone work without your desktop or Raspberry Pi server being online.
  • Can forward consent-based reports when you choose to send diagnostics, while keeping provider keys and internal maintenance details out of the app.
If Standalone is offline

Basic checks first.

  1. Check the phone has internet access. Standalone does not use your desktop or Pi server.
  2. Try again after a few minutes. Relay-backed data can intentionally serve stale cached boards during upstream problems.
  3. Check whether only radar is affected. Radar refresh and range are intentionally limited on mobile.
  4. If it still fails, use Support and include the app mode, airport, approximate time, and diagnostics setting.

Public safety note

Relay responses and cached board data are informational display aids. They can be delayed, incomplete, wrong, unavailable, or intentionally stale. Do not use them for professional or safety-critical aviation decisions.
